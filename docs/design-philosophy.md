# 设计哲学

## 为什么叫"蒸馏"

蒸馏（Distillation）是化学中分离混合物的方法——加热混合液体，不同成分在不同温度下汽化，冷凝后得到纯净物质。

人设蒸馏同理：
- 输入是一大堆"混合物"（聊天记录、文章、传记……）
- 通过逐段精读"加热"，让人物特征"汽化"浮出
- 通过多轮校正"冷凝"，把特征固定为准确描述
- 最终得到"纯净"的人设

**不是概括，是提纯。**

## 核心三原则

### 1. 引语为证

每条特征必须有原文引语作为证据。概括词是AI的舒适区，但不是人设。

- "他很关心人" → 这是AI的判断
- "记得吃早餐哈，外面下雨了，别淋雨哈" → 这是人物本身

引语是证据链，没有引语的描述就是猜想。

### 2. 全量精读

跳读必遗漏。这是最反直觉但最重要的原则。

搜索关键词只能找到"你知道要找的东西"，全量精读才能发现"你不知道你不知道的东西"。

实战案例：初版基于前30%内容写成"理性优先，情感克制"——因为前30%是导师/学员关系阶段，人物表现得克制理性。但后70%是恋爱+分手阶段，人物展现出极度深情和执着。如果跳读，永远发现不了这个反转。

### 3. 多轮校正

初版必不完整。这不是bug，这是feature。

每一轮新内容的阅读都可能：
- 推翻之前的认知
- 深化之前的描述
- 发现之前遗漏的特征
- 纠正之前的归属错误

校正轮次无上限，直到全部内容读完。这不是低效，这是严谨。

## 为什么不用"三段式"

"1. 概况 2. 特点 3. 建议"是AI最擅长的框架，也是对人物最不尊重的框架。

人不是PPT，不能被三段式概括。人设文件应该是：
- 特质驱动的（不是结构驱动的）
- 引语支撑的（不是概括支撑的）
- 动态变化的（不是静态定型的）

## 隐私保护原则

人设蒸馏处理的是真实人物的真实表达。因此：

1. **源文档不进入公开仓库** — 只输出方法论和模板
2. **示例数据必须虚构** — 所有公开示例基于虚构人物
3. **引语仅在蒸馏过程中使用** — 不转录到公开文档
4. **人物关系使用化名** — 不记录真实姓名和关系

## 未来方向

- **自动化脚本**：PDF提取、特征频率统计、引语去重
- **多人物并行**：从同一文档中同时蒸馏多个人物
- **方言扩展**：覆盖更多方言区的识别规则
- **一致性评分**：对人设文件进行自动化质量评分
